# Инструмент оценки проектов на маркетплейсах

Прототип реализует универсальный инструмент комплексной оценки и прогнозирования результатов реализации проектов на маркетплейсах. Практическая часть связана с темой дипломной работы: приложение объединяет данные Ozon и Wildberries в единую нормализованную модель, рассчитывает показатели, итоговую оценку проекта, сценарный прогноз и использует ИИ только для управленческой интерпретации уже рассчитанных агрегатов.

## Архитектура

- Next.js App Router + TypeScript.
- Tailwind CSS для интерфейса.
- Recharts для графиков.
- `scripts/prepare-data.ts` для подготовки и обезличивания выгрузок.
- `src/data/generated/normalized-records.json` как безопасная константная витрина данных.
- `src/app/api/llm/analyze/route.ts` как серверный маршрут для OpenRouter.
- Vitest для минимальных расчетных тестов.

В прототипе нет базы данных, авторизации, VPS, загрузки файлов в рабочем интерфейсе и интеграций с реальными программными интерфейсами маркетплейсов.

## Страницы

- `/source-data` показывает подготовленные обезличенные записи.
- `/dashboard` показывает интерактивный дашборд с фильтрами, расширенными показателями, воронкой, структурой выручки, топами товаров/складов/регионов и матрицей по месяцам.
- `/project-evaluation` считает итоговую оценку по четырем блокам.
- `/forecasting` строит сценарии 0.85 / 1 / 1.15.
- `/llm-analyst` отправляет обезличенные агрегированные показатели в OpenRouter.

## Локальный запуск

```bash
npm install
npm run prepare:data
npm run dev
```

Приложение откроется на `http://localhost:3000`.

## Подготовка данных

Сырые выгрузки должны лежать локально в:

```text
data/source/
```

Эта папка добавлена в `.gitignore`, потому что выгрузки могут содержать персональные или коммерчески чувствительные данные. Скрипт:

```bash
npm run prepare:data
```

удаляет колонки с персональными данными, нормализует Ozon/Wildberries к единому типу `NormalizedRecord` и пишет результат в:

```text
src/data/generated/normalized-records.json
```

В Git можно коммитить только подготовленные обезличенные данные.

## OpenRouter

Создайте `.env.local` по образцу `.env.example`:

```env
OPENROUTER_API_KEY=your_openrouter_api_key_here
OPENROUTER_MODEL=minimax/minimax-m2.5:free
OPENROUTER_BASE_URL=https://openrouter.ai/api/v1
NEXT_PUBLIC_APP_NAME=Инструмент оценки проектов на маркетплейсах
```

Если `OPENROUTER_API_KEY` не задан, приложение не падает: страница ИИ-анализа показывает предупреждение, а все расчеты и аналитические разделы остаются доступными.

## Проверка

```bash
npm test
npm run build
```

Минимальные тесты покрывают слой защиты данных, показатели, итоговую оценку и прогнозные сценарии.

## Деплой на Vercel

1. Подключите GitHub-репозиторий к Vercel.
2. Укажите команду сборки: `npm run build`.
3. Выходную директорию оставьте стандартной для Next.js.
4. Добавьте переменные окружения из `.env.example`.
5. Убедитесь, что `src/data/generated/normalized-records.json` закоммичен, а `data/source/` не попадает в Git.

Подробности есть в [docs/vercel_deployment.md](docs/vercel_deployment.md).

## Ограничения прототипа

Прототип демонстрирует исследовательскую и расчетную логику, но не является системой бизнес-аналитики, CRM или сервисом для продавцов. ИИ не выполняет расчеты и не получает сырые строки заказов, имена, телефоны, адреса, электронную почту или индексы.
